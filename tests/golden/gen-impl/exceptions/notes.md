`EXPECT_THROW(stmt, E)` names a type but not what it derives from, so by default an `E` that no header provides is reported (`mt-unknown-type`). With `exception_base` in the configuration it is generated as `class ParseError : public std::runtime_error { using std::runtime_error::runtime_error; }`, in the header whose name matches (`parse_error.h`), the first the test includes otherwise (`EmptyInput`, in `parse_error.h` too); `std::runtime_error` is somebody else's and is left alone. The class has no definitions, so there is no source; the stubs still throw `std::logic_error`, which is not a `ParseError`, so the test is red.
