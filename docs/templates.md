# Templates

mirrortest lays generated files out with [inja](https://github.com/pantor/inja)
templates. The defaults are compiled into the binary; `--templates DIR`
replaces any of them with a file of your own, for example to match a house
style for file headers or section comments.

A template only *places* text. Everything that needs a decision is computed by
the tool and handed over already formatted: how a signature is spelt, which
includes a type needs, what a stub's body is. That is deliberate. Overriding a
template cannot change what the tool infers, only where it puts it.

## Overriding

```console
$ mirrortest gen-impl tests/foo_test.cpp --out src/ --templates my-templates/
```

A file in `my-templates/` replaces the built-in template with the same relative
path. Everything else stays built in:

```
my-templates/
└── common/
    └── file_header.inja     replaces the built-in common/file_header.inja
```

- Only built-in names can be overridden. A `.inja` file that matches none is
  reported as a warning and ignored; it is nearly always a typo, and the
  alternative is an override that silently never takes effect. Use
  `--verbose` to list which templates were replaced.
- Templates use LF line endings. CRLF in an override is converted.
- A template that fails to parse, or uses a variable the tool does not provide,
  is an error naming the template and, where inja knows it, the line. Until it
  is fixed no template renders, so you are never left with half an override.
- A template may `{% include "common/file_header.inja" %}` any template, built
  in or overridden.

## Writing a template

Blocks (`{% ... %}`) on a line of their own leave no blank line behind
(`trim_blocks` and `lstrip_blocks` are on). Referring to a variable that is not
defined is an error, not an empty string.

**One quirk to know.** inja's `trim_blocks` removes the *spaces and tabs* after
a block tag as well as the newline that follows it (Jinja removes only the
newline). So

```jinja
mirrortest{% if source != "" %} from {{ source }}{% endif %}
```

renders as `mirrortestfrom tests/foo_test.cpp`: the space after `%}` is gone.
Keep a space that must survive inside an expression:

```jinja
mirrortest{% if source != "" %}{{ " from " }}{{ source }}{% endif %}
```

Objects in the view model iterate in sorted key order, not the order they were
built in. Anything whose order matters is therefore passed as an array.

## The templates

### `common/file_header.inja`

The first lines of every generated file.

| Variable | Type | Meaning |
|---|---|---|
| `file_header` | string | the `file_header` configuration text (a C++ comment, without a trailing newline), or `""` |
| `source` | string | the file the output was generated from, as given on the command line, or `""` |

Output: the optional `file_header`, then
`// Generated by mirrortest from <source>. Review every TODO(mt).`, ending in a
newline.

More templates (`impl/header.inja`, `impl/source.inja`, `gtest/test_file.inja`,
`qtest/test_file.inja`) are documented here as the backends that use them land.
